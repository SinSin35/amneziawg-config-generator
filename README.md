# Массовая генерация конфигов AmneziaWG

Скрипт создаёт клиентские конфиги AmneziaWG для сервера, поднятого через приложение **AmneziaVPN**, сразу для всего списка клиентов. Вместо ручного создания по одному в приложении: пишете имена в `clients.txt`, запускаете одну команду и получаете по файлу на каждое имя.

Логика повторяет клиент [amnezia-client](https://github.com/amnezia-vpn/amnezia-client) (сверено с релизом 5.1.0.6, AmneziaWG 3.1), поэтому клиенты, созданные скриптом, ведут себя так же, как созданные в приложении:

- ключи клиента генерируются на сервере, PSK, порт и все параметры обфускации берутся из конфига сервера (Jc, Jmin, Jmax, S1–S4, H1–H4, I1–I5 и параметры AWG 3.x: HeaderProtectionKey, ContentPaddingAddition, Rekey*, RandomTrailers и т. д.);
- IP клиента выдаётся как в приложении (последний `AllowedIPs` + 1);
- пир дописывается в конфиг сервера и применяется на лету через `syncconf`, текущие подключения не рвутся;
- клиент записывается в `clientsTable`, поэтому **виден в приложении AmneziaVPN под своим именем** и его можно отозвать там же;
- `PersistentKeepalive` выбирается как в приложении: `25-35` для AWG 3.x, иначе `25`.

Поддерживаются контейнеры `amnezia-awg2` (AWG 2.0 / 3.x, `awg0.conf`) и `amnezia-awg` (старый AWG, `wg0.conf`).

## Что нужно

**На вашем компьютере (если запускаете удалённо через `run-remote.cmd`):**

- Windows 10/11 со встроенными `ssh.exe` и `tar.exe` (компонент «Клиент OpenSSH»; проверка: `ssh -V` в терминале);
- SSH-доступ к серверу под `root` (пароль или ключ).

**На сервере:**

- Linux с уже установленным через AmneziaVPN протоколом AmneziaWG (запущенный docker-контейнер `amnezia-awg2` или `amnezia-awg`);
- `docker`, `bash`, `curl`, а также стандартные `awk`, `sed`, `grep`, `xargs` (есть в любом дистрибутиве);
- `perl` с модулями `JSON::PP`, `Compress::Zlib`, `MIME::Base64`, **только для формата `amnezia`** (на Debian/Ubuntu есть по умолчанию; иначе `apt install perl`);
- права root или доступ к docker.

Сам скрипт можно запускать и прямо на сервере, тогда ничего из списка про компьютер не нужно.

## Использование

1. Запишите имена клиентов в `clients.txt`, по одному на строку (строки с `#` игнорируются):

   ```
   TestClient1
   TestClient2
   TestClient3
   ```

2. Запустите **с компьютера** (скрипт сам передаётся на сервер, выполняется там и возвращает конфиги в папку; пароль спросят один раз):

   ```
   run-remote.cmd root@IP_СЕРВЕРА [clients.txt] [папка_вывода] [формат]
   ```

   Например:

   ```
   run-remote.cmd root@203.0.113.10 clients.txt awg-configs both
   ```

   Либо **на самом сервере**:

   ```bash
   ./gen-awg-configs.sh clients.txt ./awg-configs both
   ```

3. Получите в папке `awg-configs` по файлу на каждого клиента.

### Форматы

| Формат | Результат |
|---|---|
| `native` (по умолчанию) | `Имя.conf`: нативный конфиг AmneziaWG, импортируется в AmneziaWG и AmneziaVPN как файл |
| `amnezia` | `Имя.vpn`: ключ `vpn://…` для импорта в приложение AmneziaVPN (текстом или QR) |
| `both` | оба файла |

Повторный запуск безопасен: клиенты, которые уже есть на сервере, пропускаются, создаются только новые имена. Приватный ключ на сервере не хранится, поэтому **потерянный конфиг существующего клиента восстановить нельзя**: отзовите клиента в приложении и создайте заново.

### Переменные окружения

Задаются перед запуском на сервере: `MTU=1280 ./gen-awg-configs.sh clients.txt out both`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `FORMAT` | `native` | то же, что третий аргумент скрипта |
| `CONTAINER` | авто (`amnezia-awg2`, `amnezia-awg`) | имя docker-контейнера |
| `SERVER_IP` | определяется через `ifconfig.me` | адрес/домен для `Endpoint` |
| `DNS` | `1.1.1.1, 1.0.0.1` | DNS в клиентских конфигах |
| `MTU` | не задан (для `.vpn`: `1376`) | строка `MTU` в `.conf` / поле `mtu` в ключе (для AWG 3.1 советуют `1280`) |
| `KEEPALIVE` | авто (`25-35` / `25`) | `PersistentKeepalive` |

## Безопасность

- Файлы `.conf` и `.vpn` содержат **приватные ключи клиентов**. Передавайте их только владельцам устройств, не храните в открытом виде и не коммитьте (в `.gitignore` папки с результатами уже исключены).
- Перед изменениями скрипт делает копии `awg0.conf.bak.<время>` и `clientsTable.bak.<время>` рядом с оригиналами в контейнере (`/opt/amnezia/awg/`). Если что-то пошло не так: верните копию на место и перезапустите контейнер (`docker restart amnezia-awg2`).
- Скрипт не меняет серверные параметры обфускации, ключи сервера и PSK, только добавляет новых клиентов.

### Если вы запускаете чужой скрипт (или даёте этот другим)

- Скрипт выполняется на сервере **от root** и меняет конфиг VPN: прочитайте его перед запуском (около 200 строк), а при первом запуске попробуйте на одном тестовом клиенте.
- Имена клиентов: только латиница, цифры и `. _ -`, до 64 символов, первый символ буква или цифра. Остальные имена пропускаются с сообщением (имя попадает в имя файла, в конфиг сервера и в JSON).
- Файлы с ключами создаются с правами только для владельца (`umask 077`).
- Для определения IP скрипт обращается к `ifconfig.me` (узнаёт адрес сервера). Чтобы не обращаться к сторонним сервисам, задайте `SERVER_IP`.
- При удалённом запуске ключи клиентов недолго лежат во временной папке на сервере (создаётся с правами 700 и удаляется после копирования), а на вашем компьютере в `%TEMP%\awg-out.tar` (удаляется после распаковки).
- Подключение идёт обычным `ssh`: проверку отпечатка хоста и ключи SSH никто не подменяет, это делает ваш клиент.

## Как проверить

Для начала создайте одного тестового клиента (отдельный файл списка с одной строкой), импортируйте конфиг и подключитесь. Для сравнения с приложением создайте ещё одного клиента вручную в AmneziaVPN и сопоставьте файлы построчно: кроме ключей и IP, они должны совпасть.

## Ограничения

- Вся логика сверена с исходниками клиента для AmneziaWG 1.x–3.1; если в будущих версиях изменятся пути (`/opt/amnezia/awg/…`) или формат ключа `vpn://`, скрипт потребует обновления.
- Параметры, которые приложение хранит только у себя (например, изменённый DNS в настройках приложения), скрипту неизвестны: задавайте их переменными окружения.
- В поле «название» ключа `vpn://` подставляется имя клиента, а не имя сервера, как делает приложение.
- Одновременно с работой скрипта не создавайте клиентов в приложении (возможна гонка записи `clientsTable`).
